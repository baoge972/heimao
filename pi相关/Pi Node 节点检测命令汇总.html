⚡ Pi Node 节点诊断工具箱

一键复制命令 · 精准定位节点状态 · 同步进度解读

✅ 适用于 Docker / WSL Ubuntu / Pi Node 容器环境

📡 核心同步状态

🐳 容器内 | Ubuntu WSL
🎯 黄金命令 · 实时节点信息
/usr/bin/stellar-core --conf /opt/stellar/core/etc/stellar-core.cfg http-command info
📍 在哪执行： 先进入 Pi Node 容器内 (docker exec -it testnet2 bash) 或直接在 Ubuntu WSL 终端。
🔍 如何解读：
• "state" → Catching up (追赶中) / Synced! (已同步)
• "ledger" : { "num" : xxxxx } → 你当前的本地区块高度。
• "status" → 详细动作：例如 Downloading state file 或 Catching up。
• "peers" → "authenticated_count" → 已连接的对等节点数 (>0 即正常)。
✅ 当 ledger.num 接近最新区块且 state 为 Synced! 时同步完成。

🐙 容器与进程健康

WSL / PowerShell
📦 查看 Pi Node 容器状态
docker ps | grep testnet2
⚙️ 查看容器内所有服务
supervisorctl status
📍 执行位置： 前者在 WSL/Windows PowerShell 直接运行；后者需先进入容器 (docker exec -it testnet2 bash)。
📖 解读： 确保 stellar-core、postgresql、horizon、rpc 均为 RUNNING 状态。若有 STOPPED 进程，执行 supervisorctl start 服务名。

📜 实时日志 & 错误追踪

容器内 / WSL
📟 跟踪主节点日志 (实时)
docker logs -f testnet2
🩺 查看 supervisor 详细日志
tail -100 /var/log/supervisor/supervisord.log
💡 小技巧： 使用 docker logs --tail 50 testnet2 只看最后 50 行。
若日志中出现 ERROR / FAILED / exit status 1 可截图分析；
正常同步时会看到 Catching up... Downloading state file 或 ledger closed。

🌐 网络连接 & 对等节点

容器内执行
🔌 查看对等节点详情
/usr/bin/stellar-core --conf /opt/stellar/core/etc/stellar-core.cfg http-command peers
🧭 检查 horizon API 可用性
curl -s http://localhost:8000/ | head -20
解读： authenticated_count 建议 >=5；若为0可能网络隔离或防火墙限制。
horizon 命令应返回 "horizon" 版本信息，若失败说明 horizon 服务异常。

📊 进度监控 & 自动化刷新

实时 watch 命令
⏱️ 每 10 秒刷新同步状态
watch -n 10 '/usr/bin/stellar-core --conf /opt/stellar/core/etc/stellar-core.cfg http-command info | grep -E "state|num|status"'
📈 仅显示本地区块高度变化
watch -n 5 '/usr/bin/stellar-core --conf /opt/stellar/core/etc/stellar-core.cfg http-command info | jq -r ".info.ledger.num" 2>/dev/null || echo "需要安装jq"'
🔄 使用建议： 当节点处于 Catching up 状态时，用 watch 命令可以动态观察区块是否增长。初始同步本地高度可能长时间不变（在下载状态文件），一旦开始应用快照，ledger.num 会跳跃式增长。

🛠️ 故障诊断 & 重启操作

多环境适用
🔁 重启容器内的 stellar-core
supervisorctl restart stellar-core
♻️ 完全重置 WSL + Docker（卡顿时）
wsl --shutdown
🧹 进入容器手动执行（高级）
docker exec -it testnet2 bash
⚠️ 注意： wsl --shutdown 会关闭所有 WSL 发行版，请在关闭 Docker Desktop 后执行，然后重启电脑或重启 Docker。
如果 horizon/rpc 服务停止，使用 supervisorctl start horizon 等命令恢复。

💾 资源占用 & 磁盘健康

主机 | 容器
🖥️ 容器内存/CPU 实时统计
docker stats testnet2 --no-stream
📀 查看容器数据目录大小
du -sh /opt/stellar/core/buckets /opt/stellar/postgresql/data
💡 同步过程中 stellar-core 可能占用 1~2GB 内存，CPU 在 catchup 阶段会有波动。磁盘可用空间至少保持 30GB 以上。
若 docker stats 显示内存接近限制，可考虑增加 Docker 资源配额。

⚡ 一键健康检查脚本

容器内运行
📋 快速输出节点 + 服务 + 同步摘要
echo "=== 节点状态 ===" && /usr/bin/stellar-core --conf /opt/stellar/core/etc/stellar-core.cfg http-command info | grep -E "state|ledger.num|status" && echo -e "\n=== 服务状态 ===" && supervisorctl status | grep -E "RUNNING|FATAL" && echo -e "\n=== 最新日志摘要 ===" && tail -5 /var/log/supervisor/supervisord.log
🚀 粘贴后直接显示 同步状态、核心服务健康状况、最新错误提示，最适合日常巡检。如果看到 state 为 Catching up 且 status 包含 Downloading state file 即一切正常。
📌 同步正常时的黄金指标：
✅ "state" : "Catching up" + 下载状态文件 → 属于初始快速追赶。
✅ 对等节点 authenticated_count ≥ 5 → 网络连接健康。
✅ 服务 stellar-core 与 postgresql 均为 RUNNING。
⏳ 同步时间取决于网络与硬件，一般需要 2~6 小时，当 ledger.num 从 885万 跳跃至 894万 即表示应用快照成功。
💬 如遇长期卡顿，建议执行 wsl --shutdown + 重启电脑，但仍需避免频繁打断同步过程。
