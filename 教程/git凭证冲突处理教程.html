Git 凭证冲突处理教程
—— 推送账户与目标仓库不对应（403 Permission denied）

典型报错：
报错示例
remote: Permission to baoge972/baoge972.github.io.git denied to baoge6789.
fatal: unable to access 'https://github.com/baoge972/baoge972.github.io.git/':
The requested URL returned error: 403
一句话诊断：本机「自动登录」用的 GitHub 身份是 baoge6789，但它对目标仓库 baoge972/baoge972.github.io 没有写权限。Git 每次推送都会抢先套用缓存凭证，连弹窗重新登录的机会都不给——这就是"强生效凭证"。删除/更换凭证后即可解决。

〇、凭证藏在哪里（先搞清楚地图）

Windows 上 Git 的 HTTPS 凭证可能藏在 4 个地方，任何一个不对都会导致 403。排查/清理按此优先级从高到低：

#位置说明
1URL 内嵌凭证仓库地址写成 https://user:token@github.com/...，优先级最高，最容易"强生效"
2Windows 凭据管理器credential.helper=manager 时的缓存条目 git:https://github.com
3用户目录明文文件credential.helper=store 时写 ~/.git-credentials，可能残留多个账号
4GitHub CLI 登录态gh 命令保存的账号（本项目一般用不到）
关键点：hexo-deployer-git 每次 hexo d 会重建 .deploy_git，但它不会清除上面的系统级凭证。所以要手动清一次，之后才会恢复"弹窗登录"。

一、排查：到底是谁在替我登录

1.1 查看当前 Git 用哪个账号推送

PowerShell 复制运行
# 看凭证助手配置（manager / store / 空）
git config --global credential.helper

# 看有没有 URL 内嵌 token（最容易被忽略的"强生效"元凶）
git config --global --get remote.origin.url
type _config.yml | findstr /i repository

1.2 查看凭据管理器里的 GitHub 条目

PowerShell 复制运行
cmdkey /list | findstr /i github

看到 git:https://github.com 就说明这里有缓存，它就是自动登录的来源。

1.3 查看明文文件 ~/.git-credentials 里有几个账号

PowerShell 只查看·不泄露token
(Get-Content "$env:USERPROFILE\.git-credentials") -replace '://[^@]+@','://***@'
提示：上面这条命令会把账号:密码/token 打码成 ***，只显示用户名，安全。若出现 hexo-baoge、baoge6789 等非目标账号的行，它们就是元凶。

二、处理：删掉错误凭证（三种情况按需选用）

情况 A：凭证在「凭据管理器」里 —— 删除条目

PowerShell 复制运行
cmdkey /delete:git:https://github.com

删除后下次推送会重新弹窗要求登录，选 Sign in with browser 用正确账号（baoge972）登录即可。

情况 B：凭证在「明文文件 ~/.git-credentials」里 —— 删掉错误那一行

PowerShell 先备份再删错误账号
# 1) 先备份，万一删错可恢复
$f = "$env:USERPROFILE\.git-credentials"
Copy-Item $f "$f.bak" -Force

# 2) 只保留目标账号（把 baoge972 换成你的正确用户名）
(Get-Content $f) | Where-Object { $_ -match '@github.com' -and $_ -notmatch '://[^@]*@' -or $_ -match 'baoge972' } |
    Where-Object { $_ -match 'baoge972' } | Set-Content $f -Encoding UTF8

# 上面若嫌绕，可直接手工清空重来（推荐，最省心）：
Remove-Item $f -Force
省事做法：不想精细挑行，就直接 Remove-Item "$env:USERPROFILE\.git-credentials" -Force 整个删掉。反正已有 .bak 备份，下次推送会重新要求登录，用正确账号登录会自动生成新的凭证文件。

情况 C：URL 里内嵌了 token —— 改回干净地址

_config.yml 里 deploy 段
deploy:
  type: git
  repository: https://github.com/baoge972/baoge972.github.io.git
  branch: main

确保 repository 里没有 用户名:token@ 这种前缀；有就去掉，让它走凭据管理器/弹窗登录。

三、验证：确认凭证已生效且账号正确

3.1 用 API 反查"我现在到底是哪个账号"

PowerShell 只读·安全
# 读取明文文件里第一条 token，问 GitHub 它属于谁（只显示登录名，不打码 token 不外泄）
$line = (Get-Content "$env:USERPROFILE\.git-credentials")[0]
$tok  = ($line -replace '.*://[^:]*:([^@]+)@.*','$1')
(Invoke-RestMethod 'https://api.github.com/user' -Headers @{Authorization="token $tok"}).login

输出的登录名必须 = baoge972。若报错 401，说明该 token 已失效，同样该删。

3.2 用 SSH 方式则检查公钥对应的账号

命令 复制运行
# 会把 SSH 身份对应的 GitHub 用户名打印在 Welcome 里
ssh -T git@github.com

四、重新部署

PowerShell 复制运行
hexo clean; hexo generate; hexo deploy
成功的标志：不再出现 403 / denied to ...，而是看到：
正常输出示例
INFO  Deploy done: git
若删除凭证后第一次推送弹出 GitHub 登录窗口，用 baoge972 账号登录授权即可，之后又会"记住"正确身份。

五、防复发（可选）

  • 统一账号：浏览器、Git 弹窗、PAT 都用同一个 GitHub 账号，别混用。
  • 用 Fine-grained PAT：GitHub 生成只针对 baoge972/baoge972.github.io 仓库、只给 Contents: Write 权限的令牌，即使误用也推不到别处。
  • 改用 SSH：仓库地址用 git@github.com:...，公钥加到正确账号，能绕开 HTTPS 凭证打架的问题。
  • 换电脑/换账号时：先跑第二节命令清一次旧凭证，再登录新账号。
最省事的三板斧（记不住原理时照做）：
清凭证 + 重登录
cmdkey /delete:git:https://github.com
Remove-Item "$env:USERPROFILE\.git-credentials" -Force -ErrorAction SilentlyContinue
hexo clean; hexo g; hexo d   # 弹窗出现时，用 baoge972 登录
