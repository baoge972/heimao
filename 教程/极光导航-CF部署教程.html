一、架构概览

组件技术说明
前端Next.js 16 (Static Export)构建输出到 cf/ 目录
后端 APICF Pages Functionsfunctions/api/ 自动映射为 /api/*
数据库Cloudflare D1 (SQLite)绑定名 DB，库名 jg-nav-db
部署CF Pages + GitHub推送自动触发部署，支持私库

Pages Functions 不需要单独部署，放在 functions/ 目录下即可自动生效。
文件路径 = API 路径：functions/api/sites.ts → /api/sites

二、环境准备

  1. Node.js 20+（推荐 22 LTS）
  2. Git 并配置好 GitHub SSH/HTTPS
  3. Cloudflare 账号：dash.cloudflare.com
  4. GitHub 仓库：项目代码推送到 GitHub（私库/公库均可）
# 克隆项目后安装依赖
npm install

三、创建 D1 数据库

1登录 CF Dashboard

2左侧菜单 → Workers & Pages → D1 SQL Database

3点击 Create database

4填写名称：jg-nav-db，点击 Create

5创建成功后进入数据库详情页，记下 Database ID（格式如 6bcac328-xxxx-xxxx-xxxx）

这个 Database ID 是唯一的，下一步配置绑定和 wrangler.toml 都需要用到。

四、配置 wrangler.toml

项目根目录的 wrangler.toml 是部署核心配置，部署前必须确保 database_id 正确：

name = "jg-nav"
pages_build_output_dir = "cf"
compatibility_date = "2024-12-01"

# D1 数据库绑定
[[d1_databases]]
binding = "DB"
database_name = "jg-nav-db"
database_id = "你的真实 database_id"   ← 替换为第三步获取的 ID

# 环境变量
[vars]
STATIC_PASSWORD = "你的访问密码"

绝对不能让 database_id 保持占位符 <创建后填入>！否则 Functions 发布直接报错：
Error 8000022: Invalid database UUID

配置说明

字段说明
namePages 项目名称
pages_build_output_dirNext.js 静态输出目录，对应 next.config.ts 中的 distDir: 'cf'
bindingFunctions 中通过 env.DB 访问数据库，名称必须为 DB
STATIC_PASSWORD私密模式密码，访问者需输入此密码才能查看

修改 wrangler.toml 后推送到 GitHub，Pages 会自动重新构建部署。

五、初始化数据库（执行 SQL）

创建数据库后，表结构是空的，需要手动执行 SQL 初始化。

SQL 文件在 migrations/ 目录下，必须按顺序执行：

顺序文件内容
①0001_tables.sql建表：Site、Category、User、GlobalSettings、Wallpaper 等
②0002_seed_core.sql初始设置 + 默认管理员 + 分类
③0003_seed_sites_1.sql学习资源 + 开发工具类站点数据
④0004_seed_sites_2.sql设计灵感 + 娱乐影音 + AI 站点数据

执行方式

登录 CF Dashboard → Workers & Pages → D1 → 点击 jg-nav-db → Console

依次复制每个 SQL 文件内容，粘贴执行。每个文件单独执行，不要一次性粘贴多个文件。

D1 Console 不支持 -- 单行注释！SQL 文件中不要有 -- xxx 注释，否则会报 malformed request 错误。

也可以直接在 D1 Console 界面操作：选中一个 SQL 文件的内容 → 粘贴 → 点击 Run → 确认结果。
每执行完一个文件，确认无误后再执行下一个。

六、创建 Pages 项目

GitHub 集成部署

1登录 CF Dashboard → Workers & Pages → 点击 Create → Pages

2选择 Connect to Git → 授权 GitHub → 选择仓库

3填写构建配置：

配置项值
Framework presetNone（不要选 Next.js）
Build commandnpm run cf:build
Build output directorycf
Root directory留空（默认根目录）

Framework preset 必须选 None！不要选 Next.js 预设。我们用的是静态导出 + Functions，不是 SSR 模式。

4配置 D1 数据库绑定：

在 Pages 项目设置页 → Settings → Bindings → Add binding

配置项值
Binding typeD1 Database
Variable nameDB（必须与 wrangler.toml 一致）
D1 database选择 jg-nav-db

Variable name 必须是 DB，Functions 代码里通过 env.DB 访问数据库，名称不对会导致所有 API 报错。

5点击 Save and Deploy，等待构建完成（通常 1-2 分钟）

部署成功后 CF 会分配 xxx.pages.dev 域名。
如需自定义域名：Pages 项目 → Custom domains → Set up a custom domain → 按提示添加 DNS 记录。

七、环境变量

除了 wrangler.toml 中配置的变量，还可以在 Dashboard 设置：

Pages 项目 → Settings → Environment variables

变量名说明示例
STATIC_PASSWORD私密模式访问密码自定义

八、图标和壁纸管理

图标文件不推送

.gitignore 已排除以下目录：

/public/uploads/icons    # 上传的站点图标
/public/uploads/wallpapers  # 壁纸文件

这意味着上传的图标和壁纸文件不会推送到 GitHub。CF Pages 部署后这些文件不存在！

解决方案

  • 图标：优先使用"自动获取"模式（Google Favicon）或"品牌图标"（Iconify CDN），这两种都不需要本地文件
  • 壁纸：设置中使用 Bing 壁纸 URL 或外部图片链接，不依赖本地文件
  • 必须用本地文件时：手动上传到 CF Pages 部署后的对应路径，或使用 R2/外部图床

十、常见问题排查

1. 部署成功但页面空白

原因：D1 数据库为空，没有执行迁移 SQL。

解决：去 D1 Console 按顺序执行 migrations/ 下的 SQL 文件。

2. Functions 报错 Invalid database UUID

原因：wrangler.toml 的 database_id 是占位符。

解决：执行 npx wrangler d1 create jg-nav-db 获取真实 ID，替换到配置文件。

3. D1 Console 报 malformed request

原因：SQL 中包含 -- 单行注释。

解决：删除所有 -- 注释后再执行。

4. 上传的图标/壁纸 404

原因：这些文件在 .gitignore 中，没有推送到 GitHub。

解决：改用自动获取图标（favicon URL）或品牌图标（Iconify），壁纸用外部 URL。

5. 搜索下拉框/弹窗被遮挡

原因：父容器 overflow-x-auto 裁剪了绝对定位子元素。

解决：将对应容器的 overflow 改为 overflow-visible。

6. 编辑站点保存失败

原因：PUT /api/sites 之前只支持批量排序（Array），不支持单站点更新（Object）。

解决：已修复，PUT 同时支持 Array（批量排序）和 Object（单站点全字段更新）。

7. 密码修改后如何恢复？

在 D1 Console 执行：

UPDATE User SET passwordHash = '新密码的SHA256哈希' WHERE username = 'admin';

SHA-256 在线生成：toolhelper.cn

附录：本地开发

启动开发服务器

# 方式1：Next.js 本地开发（不含 Functions）
npm run dev

# 方式2：Wrangler 本地开发（含 Functions + 本地 D1）
npm run cf:dev

cf:dev 使用本地 SQLite 数据库，数据存在 .wrangler/state/ 目录，与线上 D1 互不影响。

关键文件结构

jg-nav/
├── app/                    # Next.js 前端页面
│   ├── components/         # 组件（site/layout/modals/settings/ui）
│   ├── page.tsx            # 主页
│   └── layout.tsx          # 布局

│   ├── settings.ts         # 全局设置
│   ├── market.ts           # 行情数据
│   ├── metadata.ts         # 网站元数据抓取
│   └── auth/               # 认证相关

│       └── account.ts      # 账号设置
├── lib/                    # 共享工具
│   ├── constants.ts        # 常量（图标映射、默认设置）
│   └── utils.ts            # 工具函数
├── migrations/             # D1 数据库迁移 SQL
├── wrangler.toml           # CF 部署配置（核心！）

└── package.json            # 脚本命令

npm 脚本说明

命令用途
npm run devNext.js 本地开发（仅前端，无 Functions）
npm run cf:build构建静态文件到 cf/ 目录（CF Pages 自动调用）
npm run cf:dev本地调试（含 Functions + 本地 D1，需安装 wrangler）

cf:dev 是本地调试用的，数据存在 .wrangler/state/ 目录，与线上 D1 互不影响。
日常开发用 npm run dev 即可，需要调试 API 时再用 cf:dev。
