OpenVPN 配置修改指南

本文档专门记录 TCP/UDP 模式下，服务端与客户端的配置文件如何修改与切换。

一、客户端配置修改（.ovpn 文件）

使用记事本打开你的 .ovpn 文件，修改以下内容：

1. Windows 防踩坑核心补丁（必加）

此段代码解决 Windows 系统下的端口耗尽、网卡假死和握手失败问题。直接添加在文件顶部：

# ===== Windows 防踩坑核心补丁 =====
disable-dco
sndbuf 393216
rcvbuf 393216
tun-mtu 1400
mssfix 1360
ping 10
ping-restart 120
ping-timer-rem
replay-window 256 30
mute-replay-warnings

2. 服务器地址与协议设置

根据服务器端修改的协议，修改客户端连接参数：

# 如果服务器端是 TCP 8443，请修改为：
proto tcp
remote 8.217.131.234 8443

# 如果服务器端是 UDP 1194，请修改为：
proto udp
remote 8.217.131.234 1194

二、服务器端配置修改

通过 SSH 登录服务器，配置文件路径通常为：/etc/openvpn/server/server.conf。

终端执行：nano /etc/openvpn/server/server.conf

1. 修改为 TCP 模式

找到 proto 和 port 行进行修改。注意：TCP 模式必须注释掉 explicit-exit-notify，否则服务无法启动报错！

proto tcp
# 注意：如果 443 端口被 Nginx 占用，请改用 8443
port 8443

# 必须注释掉下面这行！
# explicit-exit-notify 1

2. 修改回 UDP 模式

修改协议和端口，并取消注释 explicit-exit-notify：

proto udp
port 1194

# UDP 模式必须取消注释这行
explicit-exit-notify 1

3. 重启服务使其生效

每次修改完 server.conf 后，必须在服务器执行以下命令：

systemctl restart openvpn-server@server

三、修改后的必做检查

1. 查服务是否正常启动

systemctl status openvpn-server@server

如果看到 Active: active (running) 说明成功。如果是 failed，请看下一步。

2. 查报错日志

journalctl -u openvpn-server@server -n 20 --no-pager

常见报错处理：

报错信息 原因及解决
Address already in use 端口被占用。执行 sudo ss -tlnp | grep 端口号 查占用进程，换个端口（如 8443）。
--explicit-exit-notify can only be used with --proto udp TCP 模式下忘了注释掉 explicit-exit-notify 1。

3. 阿里云安全组放行

修改端口后，必须去阿里云控制台的安全组放行对应端口：

  • 如果使用 TCP 8443，放行 TCP 8443。
  • 如果使用 UDP 1194，放行 UDP 1194。
