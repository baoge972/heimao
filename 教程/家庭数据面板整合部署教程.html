大屏 + 记账 + 人情，合并为一个 Cloudflare Pages 项目 · 直接上传文件夹部署

一个 Pages 项目搞定，根目录 _worker.js 统一路由；大屏 HTML 直接内嵌在 _worker.js 里。

2建 KV（2 个）

Dashboard → Storage & databases → KV → Create a namespace：

  • jtjz_users —— 记账账号与数据
  • jiating_memo_data —— 备忘录

KV 显示名可随意，但第 4 步绑定时变量名必须是 USERS、MEMO_DATA。

3建 D1 + 建表

D1 → Create，名称 renqing-db → 进入后 Console 执行：

CREATE TABLE IF NOT EXISTS user_data_backup (id TEXT PRIMARY KEY, name TEXT, user_id TEXT, data_content TEXT, data_version TEXT, created_at TEXT, updated_at TEXT);

人情每次保存都往这张表插一条新记录，最新一条即当前数据，/rq-api/api/files 列出的就是这些历史版本。

旧数据老项目表名可能是 social_records，新库是空表。最省事：部署后在 /rq/ 用「导入」重新上传备份 JSON。

4建 Pages、上传、绑定

① 创建 + 上传

  1. Workers & Pages → Create → Pages 标签 → Upload assets（不是 Connect to Git）
  2. 项目名 jiating → 拖入 jiating-pages 文件夹
  3. Build command 留空；Build output directory 填 . → Deploy site
直接上传方式不读 wrangler.toml，里面的 KV/D1 绑定不会生效，必须控制台手点。

② 绑定：Settings → Functions → Add bindings

类型变量名（大小写一致）指向
kv_namespaceUSERSjtjz_users
kv_namespaceMEMO_DATAjiating_memo_data
d1_databaseDBrenqing-db
Pages 与 KV/D1 必须同一账户，否则下拉里根本选不到。

自定义域名（可选）：Custom domains → 如 jt.baoge666.cn。

5密钥与变量（同页 Settings → Functions）

Secrets —— 敏感项一律用密钥（加密、后台不可再查明文）

名称值作用
ADMIN_PASSWORD8888大屏访问密码门（仅决定能否查看大屏，签发 dash_auth）；不配提示“服务器未配置密码”
SOCIAL_AUTH_CODEbaoge888，多个逗号分隔 baoge888,baoge777人情页 /rq/ 授权码，兼作“管理密码”：订阅设置/数据源、备忘录读写都要它（签发 mng_auth）；不配则你自己也改不了

Environment variables —— 非敏感用文本变量

名称作用
VPS_DATA_URL大屏"云服订阅"数据源
PHONE_COST_URL大屏"手机套餐"数据源
DOMAINS_DATA_URL大屏"域名监控"数据源

不配只影响对应卡片。数据文件可直接放在同一项目里，变量填 https://域名/vps.txt。

可被前端覆盖这三个变量只是“默认值”。部署后可在大屏 订阅区 ⚙️ 设置里直接改数据源 url（存进 KV MEMO_DATA，改后以 KV 为准；某项清空则自动回退到这里的环境变量）。改 url / 存配置都要管理密码（SOCIAL_AUTH_CODE）。
无需配置本面板只需要 ADMIN_PASSWORD、SOCIAL_AUTH_CODE 两个密钥 + 三个数据源变量。ACCOUNTING_USER / ACCOUNTING_PASS（原用于自动建 family 默认账号）与 MEMO_PASSWORD（备忘录密码门连同 /api/auth/memo 接口已删除）都已不再被代码引用，从来没配过就不用管；若旧项目里残留，删掉也无影响。

6鉴权模型（改造后的关键变化）

位置验证看谁的数据
大屏 /要访问密码（ADMIN_PASSWORD）登录成功下发 HttpOnly Cookie dash_auth（30 天）；仅决定“能否查看大屏”，登录态由服务端 dashboard-check 校验（不再凭 localStorage 放行）；“退出”会清除
大屏 · 家庭账本卡片要，卡片内"登录记账"你登录的那个账号（token 存 accounting_card_token）
大屏 · 备忘录卡片看和改都要“管理密码”（SOCIAL_AUTH_CODE）：点“管理”每次弹框，GET/POST /api/memo 均校验 mng_auth全局一份
大屏 · 订阅设置 ⚙️每次进入都要“管理密码”（SOCIAL_AUTH_CODE，验证前不暴露配置）展示配置全局一份（存 KV），数据源 url 可改
大屏 · 人情卡片不要，走开放接口 /rq-api/api/social-stats只有汇总数字，无明细
记账本 /jz/要账号登录自助注册，已去掉邀请码；用户间数据隔离
人情本 /rq/要授权码，每次进入都要重新输入服务端比对 SOCIAL_AUTH_CODE → 下发 HttpOnly Cookie rq_auth 供数据接口放行；前端已取消"记住登录"自动放行
  • 授权码不写在前端，改服务端变量校验；/rq-api 除 /api/health、/api/social-stats 外，无合法 Cookie 一律 401——绕过遮罩也拿不到数据。
  • family 默认用户已移除。旧 KV 里若有，不影响运行；想清干净就删 user:family、userid:<uuid>、data:<uuid>（uuid 在 user:family 的 value 里）。
  • 记账卡片固定统计本月；分类排行上限 16 条（超出仍计入总额）；高度不会被截断。
  • 两级密码：ADMIN_PASSWORD=访问（dash_auth，只看大屏）；SOCIAL_AUTH_CODE=管理（mng_auth，改订阅设置/数据源、读写备忘录）。订阅配置与备忘录存于 MEMO_DATA（全局一份），读写接口凭 mng_auth 放行；两枚 Cookie 都带 Secure，HTTP 下不生效，必须 HTTPS 部署。

7订阅区配置 & 大屏初始模式（_worker.js）

① 订阅区：一份代码，运行时随意勾选

用 _worker-订阅可配置.js（改名成 _worker.js 放进 jiating-pages/）即可，不用再按对象换文件。大屏底部“订阅”卡片有 ⚙️ 设置，点开可随意勾选展示哪几张卡（📱 手机 / ☁️ 云服 / 🌐 域名，0~3 张任意组合），并给每张卡单独设时长、设订阅区总时长；折叠名称、顺序、标签栏全部自动跟随。

想要的效果怎么做
自己用，三张全展示⚙️ 里三张都勾选
分享别人，只留 📱 手机⚙️ 取消“云服”“域名”，只留“手机”（＝旧的仅手机版）
一张都不展示三个全不勾，订阅区自动收起
每次点 ⚙️ 都要输管理密码（SOCIAL_AUTH_CODE，居中弹窗），验证通过才显示配置与数据源。配置存 MEMO_DATA、全局一份：一次设置所有设备跟随（代价是不能各设备各勾各的）。面板里还能直接改三个数据源 url，改后以 KV 为准、留空＝回退 §5 环境变量。

② 大屏初始模式：轮播还是固定（_worker.js 约 2800 行）

大屏布局有两种：轮播（单张卡片大图、每隔几秒切一张）与固定（三列平铺、一次看全部）。初始表现由紧邻的两行决定：

// 约 2800 行附近
const isAutoPlay = ref(false);    // 是否自动播放
const viewMode = ref('grid');     // 'carousel'=轮播  'grid'=固定
想要的初始效果isAutoPlayviewMode
打开即固定三列、完全不转（给别人推荐）false'grid'
轮播布局但初始暂停，点顶部 ▶️ 才转false'carousel'
轮播布局且打开就自动播放（最原始）true'carousel'

顶部 📋固定 / 🔄轮播 按钮可随时互切；一旦切到轮播，代码会自动开始播放（toggleViewMode 内强制 isAutoPlay = true），所以这两个初值只决定"刚打开"那一下的状态。

现成默认：订阅可配置版 = 固定（isAutoPlay=false, viewMode='grid'），打开即三列平铺不转。要轮播布局，把 viewMode 改回 'carousel' 即可；改完运行 node --check _worker.js 确认无语法报错再上传。

③ 管理与展示分离：隐藏的 /admin 页 + 显示模式（本版新增）

大屏上的管理入口（订阅区 ⚙️、记账/人情“👆 点击查看完整数据源”、备忘录“👆 点击管理”、域名“管理 →”）默认都直接显示。若想让大屏纯展示、把这些管理按钮全收起来：

  • 用一个隐藏地址 https://域名/admin 切两种模式——大屏没有任何链接指过去，观众不知道它的存在，只有你手敲才进得去。
  • 进 /admin 需管理密码 SOCIAL_AUTH_CODE（复用 /api/auth/management，与订阅设置同一把钥匙；不是大屏访问密码）。
  • 两种模式：管理+展示（现状，按钮都在）/ 仅展示（隐藏上面所有管理入口）。全局存一份（KV MEMO_DATA 的 display_mode），切一次所有设备跟随。
安全不降级：仅展示只是“藏按钮”，真正的写接口（/api/memo、/api/cost-admin、/api/display-mode POST）本就要求管理码，没码一律 401。所以把大屏挂电视 / 给别人看也改不动数据。

用哪个文件：把 _worker-带admin模式.js（=“订阅可配置版” + 本功能）改名成 _worker.js 放进 jiating-pages/ 上传；不需要这功能就仍用 _worker-订阅可配置.js。

用法：部署后进 /admin → 输管理密码 → 选“仅展示” → 保存 → 刷新大屏即隐藏；要再管理回 /admin 切回。

8验收（把 域名 换成实际域名）

  1. https://域名/ 输密码进得去，无"服务器未配置密码"。
  2. 访问 /jz/ 注册：只有用户名/密码/确认密码，无邀请码；注册后记账、刷新数据还在。
  3. 大屏账本卡片点"登录记账"，用上一步账号登录 → 显示该账号本月数据。
  4. 未登录时大屏停在访问密码门（ADMIN_PASSWORD）。备忘录卡片默认不显示内容；点“管理”每次弹管理密码（SOCIAL_AUTH_CODE），通过后才能看/改。直接访问 /api/memo 未带管理 Cookie → 401。
  5. 点订阅区 ⚙️：每次弹管理密码（SOCIAL_AUTH_CODE）框 → 通过后才能看/改配置；勾选、改时长、改数据源 url 后点“完成”提示保存成功；换设备或刷新后配置跟随（全局一份）；数据源 url 清空 → 回退环境变量。
  6. 大屏人情卡片免验证就有汇总数字。
  7. 访问 /rq/ 弹授权码框：错码提示错误，对码加载明细；刷新或重开页面都会再次要求输入（已按要求取消免输入）。
  8. 新标签打开 https://域名/rq-api/api/files → 返回 {"success":false,"error":"未授权：请先输入有效授权码"}（说明保护生效）。
人情页已改为每次进入都要输入授权码（不再凭 Cookie 免输入）；Cookie 与 localStorage 按设备各存，只用于数据接口放行。

9更新与排错

更新：改文件 → Deploys → 重新上传 jiating-pages → 等 Success → Ctrl+F5 或无痕验证。改了 Secret/变量若没自动产生新部署，手动 Redeploy 一次。重传只换代码，KV/D1 数据不受影响。
