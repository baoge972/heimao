Cloudflare Workers 部署

☁️ Serverless
1

前置准备

  • 一个 Cloudflare 账号（免费即可）
  • 无需服务器、无需安装软件，全程浏览器操作
  • 免费额度：每天 10 万次请求 + KV 读写，个人使用完全够用
2

创建 Worker

  • 登录 Cloudflare Dashboard，左侧进入 Workers & Pages
  • 点击 Create → Create Worker，命名如 ghostlink
  • 点击 Deploy 部署默认模板，再点 Edit code 进入编辑器
3

创建 KV 并绑定

  • Worker 管理页 → Settings → Variables
  • 找到 KV Namespace Bindings → Add binding
  • Variable name 填：GHOST_KV（必须全大写，一字不差）
  • KV namespace 选 Create new，命名如 ghostlink-db，创建后选中它
  • 点 Save
为什么必须叫 GHOST_KV？ 代码用 env.GHOST_KV 读写存储，绑定名不一致会直接报错。
4

设置后台密码

  • 同一页 Environment Variables → Add variable
  • Variable name 填：ADMIN_PASSWORD
  • Value 填你的密码（如 my_secret_2024）
  • 点 Save and Deploy
密码放在环境变量里，即使代码泄露也拿不到密码。代码留了兜底 || "8888"，不设也能跑，但不建议。
5

粘贴 Worker 代码并部署

回到 Edit code，删掉默认代码，点击下方按钮复制完整代码后粘贴，点 Deploy。

6

访问与验证

  • 部署完成后，Cloudflare 提供 *.workers.dev 域名，直接打开
  • 输入 ADMIN_PASSWORD 里设置的密码登录
  • 写测试内容 → 选查看次数和有效期 → 生成链接
  • 用无痕窗口打开链接能看到内容；刷新后显示 404 即成功
绑定自定义域名：Worker → Settings → Domains & Routes → Add Custom Domain，按提示加 DNS 记录，HTTPS 自动配置。
7

常见问题

  • 报 env.GHOST_KV 未定义：KV 绑定变量名没写成 GHOST_KV，回 Settings 检查
  • 密码一直错误：环境变量名必须是 ADMIN_PASSWORD，改完要点 Save and Deploy
  • 生成的链接打开 404：链接已过期或被查看过，KV 已自动删除，属正常阅后即焚行为
  • 想改密码：改环境变量值 → Save and Deploy，无需动代码

虚拟机 / VPS 部署

🖥️ Node.js + cloudflared
1

前置准备

  • 一台能跑 Node.js 的服务器（VPS、虚拟机、甚至家宽设备均可）
  • Node.js 16 或以上（node -v 检查）
  • 一个 Cloudflare 账号 + 一个域名（用于创建 Tunnel）
  • 服务器能访问外网（下载 cloudflared 二进制需要）
2

创建 Cloudflare Tunnel 并获取 Token

  • 登录 Cloudflare Dashboard → Zero Trust → Networks → Tunnels
  • 点击 Create a tunnel，选择 Cloudflared，命名如 ghostlink
  • 在安装页复制那串 eyJ... 开头的 Token（后面填进代码）
  • 在 Public Hostname 里绑定你的域名，Service 指向 http://localhost:30185
Token 和域名属于私密信息，不要截图外传。代码里预留了位置，部署时填进去即可。
3

上传并配置代码

  • 在服务器上创建目录，如 mkdir -p /opt/ghostlink && cd /opt/ghostlink
  • 点击下方按钮复制 index.js，保存到该目录
  • 打开文件，把顶部的 ARGO_DOMAIN 和 ARGO_AUTH 填成你自己的域名和 Token
  • 把 ADMIN_PASSWORD 改成你的密码

4

启动服务

  • 直接启动：node index.js
  • 后台守护（推荐）：npm i -g pm2 && pm2 start index.js --name ghostlink && pm2 save
  • 日志中看到 [系统] ✅ 本地服务已启动 和 [Cloudflare] Registered tunnel connection 即成功
首次启动会自动下载 cloudflared 到 ./tmp/cloudflared_bin，需要服务器能访问 GitHub。若下载失败，可手动下载后放到该路径并 chmod +x。
5

访问与验证

  • 浏览器打开你绑定的域名（如 https://ghost.yourdomain.com）
  • 输入 ADMIN_PASSWORD 里设置的密码登录
  • 生成一条测试链接，用无痕窗口打开并刷新，验证阅后即焚
6

常见问题

  • 日志报 Cannot find module 'xxx'：这套代码零依赖，只需 Node 自带模块；若报错请确认 Node 版本 ≥ 16
  • cloudflared 下载失败：服务器访问 GitHub 受限。可手动下载 cloudflared-linux-amd64 放到 ./tmp/cloudflared_bin 并 chmod 775
  • 隧道连上但域名 502：检查 Public Hostname 的 Service 是否指向 http://localhost:30185，且本地服务已启动
  • 重启后数据丢失：VPS 版把内容存在进程内存（vault 对象）里，重启即清空；需要持久化可改用 Redis 或 SQLite
  • 想换端口：改代码顶部 PORT，同时改 Tunnel 的 Service 地址
