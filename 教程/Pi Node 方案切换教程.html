一、方案概述

本教程适用于已使用 OpenVPN + Gost 方案稳定运行 Pi Node 的用户，目标是迁移到 Xray + Gost 方案，同时保留一键回退能力。

对比项 OpenVPN 方案（原） Xray 方案（新）
组网工具 OpenVPN Xray（VLESS / VMess / SS）
端口映射工具 Gost（不变）
Gost 目标地址 10.8.0.2（VPN 虚拟 IP） 127.0.0.1（本地回环）
本地客户端 OpenVPN GUI v2rayN / Clash 等
💡 核心理念： Gost 配置文件已经备份并修改，只需切换隧道工具 + 重启 Gost，即可在两种方案间自由切换。

二、准备工作

2.1 确认当前环境

  • ✅ Pi Node 正在运行（Docker 正常）
  • ✅ OpenVPN 已连接，节点端口可用
  • ✅ 能通过 SSH 登录云服务器
  • ✅ 本地已安装 v2rayN 或类似 Xray 客户端
  • ✅ s-ui 面板已配置好可用的 VLESS / VMess / SS 节点

2.2 备份服务器端 Gost 配置

# 在云服务器上执行（备份当前配置） cp /etc/gost/config.json /etc/gost/config.json.openvpn.bak
# 确认备份成功 ls -la /etc/gost/config.json*

2.3 准备 Xray 客户端

  • 在本地电脑打开 v2rayN
  • 从 s-ui 面板复制一个可用的节点链接（VLESS / VMess / SS 均可）
  • 导入并连接，确认节点状态为 已连接
  • 记住本地 SOCKS5 代理端口（默认 10100，按实际填写）

三、迁移执行（OpenVPN → Xray）

⚠️ 执行前提醒： 迁移过程中 Pi Node 会短暂离线（约 1-2 分钟）。建议在节点低峰时段操作。

3.1 在云服务器上修改 Gost 配置

将 Gost 转发目标从 OpenVPN 虚拟 IP（10.8.0.2）改为本地回环（127.0.0.1）。

# 替换所有 10.8.0.2 为 127.0.0.1 sed -i 's/10.8.0.2/127.0.0.1/g' /etc/gost/config.json
# 验证替换结果（应看到 127.0.0.1） cat /etc/gost/config.json | grep 127.0.0.1

3.2 本地电脑：断开 OpenVPN，连接 Xray

  1. 断开 OpenVPN：右键系统托盘 OpenVPN 图标 → 点击 "Disconnect"
  2. 连接 Xray 节点：在 v2rayN 中启用已导入的节点
  3. 确认代理端口：确保 SOCKS5 代理端口（如 10100）已开启

3.3 在云服务器上重启 Gost

# 重启 Gost 加载新配置 systemctl restart gost
# 检查端口监听状态 netstat -tulnp | grep -E '3140[0-9]'

四、验证与测试

4.1 在线端口检测

访问以下工具，输入服务器 IP 8.217.131.234，检测 31401 端口状态：

  • https://pi-mods.de/nodeports/
  • https://www.yougetsignal.com/tools/open-ports/
✅ 成功标志： 31401 端口显示为 Open，说明迁移成功！

4.2 Pi Node 状态检查

  • 打开 Pi Node 软件，点击 "Check Now" 检测端口
  • 点击 "Start Node" 确保节点正常运行
  • 观察区块高度是否在持续增长

五、回退流程（Xray → OpenVPN）

🔄 任何时候觉得新方案不稳定，都可以按以下步骤完整回退。

5.1 本地电脑：断开 Xray，连接 OpenVPN

  1. 断开 Xray 节点：在 v2rayN 中停止或断开当前节点
  2. 连接 OpenVPN：右键系统托盘 OpenVPN 图标 → 点击 "Connect"
  3. 等待 OpenVPN 连接成功（获取到虚拟 IP 10.8.0.2）

5.2 在云服务器上恢复 Gost 配置

# 恢复 OpenVPN 版本的配置 cp /etc/gost/config.json.openvpn.bak /etc/gost/config.json
# 验证恢复结果（应看到 10.8.0.2） cat /etc/gost/config.json | grep 10.8.0.2

5.3 重启 Gost

# 重启 Gost 加载旧配置 systemctl restart gost
# 确认端口状态 netstat -tulnp | grep -E '3140[0-9]'
✅ 回退完成： 再次检测 31401 端口，应恢复为 Open 状态。

六、常见问题

Q1：切换后 31401 端口显示 Closed

  • 检查本地 Xray 节点是否正常连接（v2rayN 中状态应为绿色）
  • 检查 v2rayN 的 SOCKS5 代理端口是否正确（如 10100）
  • 检查云服务器安全组是否放行了 31401-31409 端口
  • 尝试重启 Gost：systemctl restart gost

Q2：切换后 Pi Node 无法同步区块

  • Pi Node 需要时间同步，等待 10-30 分钟
  • 检查 Docker 是否正常运行：docker ps
  • 查看 Gost 日志：journalctl -u gost -f

Q3：v2rayN 连接节点正常，但端口检测不通

  • 确认 Gost 配置中的目标地址是 127.0.0.1 而非 10.8.0.2
  • 检查服务器上 Gost 是否正在运行：ps aux | grep gost
  • 检查防火墙是否放行端口：iptables -L -n | grep 31401

Q4：两种方案的文件对应关系

方案 Gost 配置文件 目标地址 本地客户端
OpenVPN /etc/gost/config.json.openvpn.bak 10.8.0.2 OpenVPN GUI
Xray /etc/gost/config.json 127.0.0.1 v2rayN
