一、方案概述

本教程提供两套完整方案，用于在家庭宽带无公网 IP 的环境下为 Pi Node 提供入站连接。您可以在 OpenVPN + Gost 和 Xray (karing) + FRP 之间自由切换。

对比项OpenVPN + GostXray (karing) + FRP
组网/隧道工具OpenVPNXray（通过 karing 客户端）
端口转发工具GostFRP
转发目标地址10.8.0.2（VPN 虚拟 IP）127.0.0.1（在 frpc 中配置）
本地客户端OpenVPN GUIkaring + frpc
云服务器组件Gost + OpenVPN Serverfrps

二、准备工作

  • ✅ Pi Node 正在运行（Docker 或本地模式）
  • ✅ 能通过 SSH 登录云服务器
  • ✅ 本地已安装 karing 客户端，并配置好可用的 Xray 节点（VLESS / VMess）
  • ✅ 确认 karing 的本地 SOCKS5 代理端口（本教程示例为 3067）
💡 提示： 如果当前正在使用 OpenVPN 方案，建议先备份 Gost 配置：cp /etc/gost/config.json /etc/gost/config.json.openvpn.bak

三、云服务器：安装并配置 FRP 服务端 (frps)

# 下载并解压 FRP cd ~ wget https://github.com/fatedier/frp/releases/download/v0.69.1/frp_0.69.1_linux_amd64.tar.gz tar -zxvf frp_0.69.1_linux_amd64.tar.gz
# 配置 frps.toml nano ~/frp_0.69.1_linux_amd64/frps.toml

写入以下内容（端口和 token 请按实际情况修改）：

bindPort = 7000 auth.token = "your_secure_token_here"
⚠️ 别忘了在云服务器安全组中放行端口： 7000（FRP 控制端口）和 31400-31409（Pi Node 数据端口）。

四、将 frps 配置为 systemd 服务（开机自启）

# 一键创建服务文件（路径已固定） sudo tee /etc/systemd/system/frps.service > /dev/null << 'EOF' [Unit] Description=FRP Server After=network.target [Service] Type=simple WorkingDirectory=/root/frp_0.69.1_linux_amd64 ExecStart=/root/frp_0.69.1_linux_amd64/frps -c /root/frp_0.69.1_linux_amd64/frps.toml Restart=on-failure RestartSec=5 [Install] WantedBy=multi-user.target EOF
# 重新加载 systemd，启动 frps 并设置开机自启 sudo systemctl daemon-reload sudo systemctl start frps sudo systemctl enable frps sudo systemctl status frps
✅ 预期输出： Active: active (running)

五、停止 Gost（释放端口给 FRP）

FRP 方案下不需要 Gost，必须停止它，否则端口冲突。

# 使用 gost.sh 脚本停止 Gost cd ~ && ./gost.sh

根据菜单提示，输入 5 选择 停止 gost。

# 确认 Gost 已停止 ps aux | grep gost
💡 说明： Gost 的配置文件（指向 10.8.0.2）无需修改，只需停止服务即可。

六、本地 FRP 客户端 (frpc) 配置

6.1 下载 Windows 版 FRP

  • 从 GitHub FRP Releases 下载 frp_0.69.1_windows_amd64.zip
  • 解压到本地目录，例如 D:\Edge浏览器\frp_0.69.1_windows_amd64

6.2 创建 frpc.toml 配置文件

# frpc.toml 示例（将 IP、端口、token 替换为实际值） serverAddr = "你的云服务器公网IP" serverPort = 7000 auth.token = "your_secure_token_here" # 关键：通过本地 karing 的 SOCKS5 代理连接服务器 transport.proxyURL = "socks5://127.0.0.1:3067" [[proxies]] name = "pi_31401" type = "tcp" localIP = "127.0.0.1" localPort = 31401 remotePort = 31401 [[proxies]] name = "pi_31402" type = "tcp" localIP = "127.0.0.1" localPort = 31402 remotePort = 31402 [[proxies]] name = "pi_31403" type = "tcp" localIP = "127.0.0.1" localPort = 31403 remotePort = 31403
💡 关键说明： localIP = "127.0.0.1" 指向您本地电脑自己的 127.0.0.1，因为 Pi Node 就运行在本地，这是完全正确的。

七、本地 frpc 开机自启（Windows）

让 frpc 在 Windows 开机时自动启动，无需手动操作。

7.1 创建 start_frpc.bat 批处理文件

在 FRP 目录（如 D:\Edge浏览器\frp_0.69.1_windows_amd64）下，新建一个文本文件，命名为 start_frpc.bat，写入：

@echo off cd /d D:\Edge浏览器\frp_0.69.1_windows_amd64 frpc -c frpc.toml

7.2 添加到 Windows 开机启动项

  1. 按 Win + R，输入 shell:startup，回车
  2. 把 start_frpc.bat 复制到这个打开的文件夹里
✅ 完成： 下次电脑重启后，frpc 会自动启动并运行。当前正在运行的 frpc 窗口请保持最小化，不要关闭。

八、从 OpenVPN 迁移到 Xray + FRP

⚠️ 迁移过程中 Pi Node 会短暂离线（约 1-2 分钟）。

8.1 本地电脑：断开 OpenVPN，连接 Xray (karing)

  1. 断开 OpenVPN：右键系统托盘 OpenVPN 图标 → 点击 "Disconnect"
  2. 打开 karing 并连接 Xray 节点：确保节点状态为“已连接”
  3. 确认代理端口：在 karing 设置中确认 SOCKS5 代理端口为 3067

8.2 云服务器：停止 Gost（FRP 已开机自启，无需手动启动）

# 运行 gost.sh 停止 Gost cd ~ && ./gost.sh

根据菜单提示，输入 5 选择 停止 gost。

# 确认 frps 正在运行（systemd 会自动启动） sudo systemctl status frps

8.3 启动 FRP 客户端

双击 start_frpc.bat 或直接在 PowerShell 中执行：

frpc -c frpc.toml
✅ 成功标志： 日志输出 start proxy success 字样。

九、验证与测试

9.1 在云服务器上验证端口是否可达

# 在云服务器上测试本地回环端口 curl http://127.0.0.1:31401/health
✅ 预期返回： {"database_connected":true,"core_up":true,"core_synced":true}

9.2 在线端口检测

访问 https://tools.picn.cc/，输入服务器 IP，检测 31401 端口状态。

9.3 Pi Node 状态检查

  • 打开 Pi Node 软件，点击 "Check Now" 检测端口
  • 观察 Incoming connections 数量，应该会从 0 开始逐渐增加

十、回退流程（FRP → OpenVPN + Gost）

🔄 如果 Xray + FRP 方案不稳定，或需要快速切回，按以下步骤操作。

10.1 本地电脑：断开 karing，连接 OpenVPN

  1. 在 karing 中断开 Xray 节点连接
  2. 启动 OpenVPN GUI，重新连接 OpenVPN 服务
  3. 等待连接成功，确认获取到虚拟 IP 10.8.0.2
  4. 关闭 frpc 窗口（按 Ctrl+C 终止）

10.2 云服务器：停止 FRP，启动 Gost

# 停止 FRP 服务端 sudo systemctl stop frps
# 使用 gost.sh 启动 Gost cd ~ && ./gost.sh

根据菜单提示，输入 4 选择 启动 gost。

# 确认 Gost 正在运行 ps aux | grep gost
✅ 回退完成： 再次检测 31401 端口，应恢复为 Open 状态。

十一、常见问题与经验总结

Q1：FRP 客户端报错 port unavailable

  • 原因： 云服务器上 Gost 还在运行，占用了 31401-31403 端口。
  • 解决： 用 ./gost.sh 停止 Gost，再启动 frpc。

Q2：FRP 客户端报错 connection refused

  • 检查 1： 本地 karing 是否已开启并连接？SOCKS5 代理端口是否正确？
  • 检查 2： 云服务器安全组是否放行了 7000 和 31400-31409 端口？
  • 检查 3： 云服务器上 frps 是否正在运行（sudo systemctl status frps）？

Q3：切换方案时需要修改 Gost 配置吗？

  • 不需要。 切换时只需用 ./gost.sh 启动或停止 Gost 服务。
  • FRP 方案下 Gost 必须停止，OpenVPN 方案下 Gost 必须启动。
  • Gost 的配置文件（指向 10.8.0.2）本身无需修改。

Q4：frps 如何管理？

操作命令
启动sudo systemctl start frps
停止sudo systemctl stop frps
重启sudo systemctl restart frps
查看状态sudo systemctl status frps
查看日志sudo journalctl -u frps -f

Q5：本地 frpc 如何管理？

操作方法
启动双击 start_frpc.bat
停止按 Ctrl+C 终止窗口
开机自启已通过 shell:startup 文件夹实现
