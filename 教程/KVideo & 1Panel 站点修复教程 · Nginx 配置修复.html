🔧 KVideo & 1Panel · 站点修复教程

🐧 Nginx 配置修复 🔐 SSL 证书独立签发 ⚙️ 清理 quic 参数冲突 📋 一键复制命令

解决「证书域名不匹配」 + 「请求被路由到错误后端」问题 | 基于实际服务器环境

✅ 问题现象

🔹 访问 kvideo.baoge123.de5.net 返回 MoonTV Plus 页面
🔹 访问 1p.baoge123.de5.net 证书显示为 kvideo 的证书
🔹 浏览器报错：ERR_CERT_COMMON_NAME_INVALID
🔹 nginx -t 报错：invalid parameter "quic"

📌 根本原因
1️⃣ 科技lion 生成的配置文件包含 quic 参数，当前 Nginx 不支持 → 配置文件未加载
2️⃣ Nginx 默认 include 路径不包含 /home/web/conf.d/ → 配置未生效
3️⃣ 多个站点共用了同一张 SSL 证书 → 域名与证书不匹配
4️⃣ MoonTV Plus 的配置优先级过高，错误捕获了 kvideo 域名

1 清理冲突的 Nginx 配置文件
删除旧的、包含 quic 参数的配置
# 删除可能残留的旧配置（避免干扰）
rm -f /etc/nginx/conf.d/kvideo.baoge123.de5.net.conf
rm -f /etc/nginx/conf.d/1p.baoge123.de5.net.conf
rm -f /home/web/conf.d/kvideo.baoge123.de5.net.conf
rm -f /home/web/conf.d/1p.baoge123.de5.net.conf
2 为每个站点独立申请 SSL 证书
kvideo 站点证书
certbot certonly --standalone -d kvideo.baoge123.de5.net \
  --non-interactive --agree-tos \
  --email admin@baoge123.de5.net --force-renewal
1Panel 站点证书
certbot certonly --standalone -d 1p.baoge123.de5.net \
  --non-interactive --agree-tos \
  --email admin@baoge123.de5.net --force-renewal
💡 如果提示 80 端口被占用，先停止占用进程：systemctl stop nginx，申请完成后重新启动。
3 创建 kvideo 的纯净 Nginx 配置（无 quic）
写入 /etc/nginx/conf.d/kvideo.conf
cat > /etc/nginx/conf.d/kvideo.conf << 'EOF'
server {
    listen 80;
    server_name kvideo.baoge123.de5.net;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name kvideo.baoge123.de5.net;

    ssl_certificate /etc/letsencrypt/live/kvideo.baoge123.de5.net/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/kvideo.baoge123.de5.net/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:3100;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
EOF
4 创建 1Panel 的纯净 Nginx 配置（无 quic）
写入 /etc/nginx/conf.d/1p.conf
cat > /etc/nginx/conf.d/1p.conf << 'EOF'
server {
    listen 80;
    server_name 1p.baoge123.de5.net;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name 1p.baoge123.de5.net;

    ssl_certificate /etc/letsencrypt/live/1p.baoge123.de5.net/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/1p.baoge123.de5.net/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:18227;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
EOF
5 验证配置并重载 Nginx
测试配置语法 + 重载
nginx -t && nginx -s reload
测试站点访问
# 预期返回 HTTP/2 200
curl -I https://kvideo.baoge123.de5.net
curl -I https://1p.baoge123.de5.net

🚀 一键修复脚本（全自动）

cat > /etc/nginx/conf.d/kvideo.conf << 'EOF'

    ssl_certificate_key /etc/letsencrypt/live/kvideo.baoge123.de5.net/privkey.pem;
    location / {
        proxy_pass http://127.0.0.1:3100;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;

    }
}
EOF

cat > /etc/nginx/conf.d/1p.conf << 'EOF'
