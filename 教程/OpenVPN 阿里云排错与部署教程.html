🛡️ OpenVPN 部署与排错指南

针对阿里云环境的典型问题与解决方案

🚨 典型故障：TLS Error 超时

如果你在客户端日志中看到以下报错：

TLS Error: TLS key negotiation failed to occur within 60 seconds (check your network connectivity)
TLS Error: TLS handshake failed

这通常意味着 客户端无法与服务器的 1194 端口建立有效通信。请依次排查以下三个核心环节。

第一步：排查服务端监听地址

登录到服务器，检查 OpenVPN 是否在监听正确的 IP。执行以下命令：

sudo ss -ulnp | grep 1194

错误情况（阿里云常见）：

UNCONN 0 0 172.19.60.189:1194 0.0.0.0:* users:(("openvpn",...))

此时 OpenVPN 只绑定了内网 IP，公网流量无法进入。

正确情况：

UNCONN 0 0 0.0.0.0:1194 0.0.0.0:* users:(("openvpn",...))
修复方法：修改配置文件，注释掉 local 指令。
执行下方命令打开文件：
nano /etc/openvpn/server/server.conf
找到 local 172.19.x.x，在行首加 # 号注释，保存后执行重启命令：
systemctl restart openvpn-server@server

第二步：阿里云 NAT 映射终极方案

如果监听地址已经变成 0.0.0.0，但客户端依然 TLS 超时。这是因为阿里云的公网 IP 是 NAT 映射的（不在网卡上），导致服务器回包时的源 IP 错误。

解决方案：强制 OpenVPN 绑定公网 IP 并配置转发。
  1. 修改服务端配置文件： 
    nano /etc/openvpn/server/server.conf
  2. 在文件顶部添加一行，写死你的公网 IP（去掉之前的注释）： 
    local 8.217.131.234
    *注意：请将 8.217.131.234 替换为你自己的公网IP
  3. 保存并重启服务： 
    systemctl restart openvpn-server@server
  4. 再次确认监听状态（此时应显示公网IP）： 
    sudo ss -ulnp | grep 1194

第三步：服务器内部转发与防火墙

确保服务器允许数据包转发，并配置 NAT 伪装，否则客户端连上也无法上网。

1. 开启内核转发

echo "net.ipv4.ip_forward=1" >> /etc/sysctl.conf
sysctl -p

2. 配置 iptables NAT 伪装

假设你的主网卡名称为 eth0（可通过 ip addr 查看），执行：

iptables -t nat -A POSTROUTING -s 10.8.0.0/24 -o eth0 -j MASQUERADE

3. 放行 UDP 端口

确保服务器内部防火墙没有拦截 UDP 1194 端口。放行命令：

iptables -I INPUT -p udp --dport 1194 -j ACCEPT

第四步：云服务商安全组

最后，不要忘记在阿里云等云平台的控制台 -> 安全组中，添加一条入方向规则：

  • 协议类型：UDP
  • 端口范围：1194
  • 源地址：0.0.0.0/0
按照此教程操作，99% 的 OpenVPN 握手失败问题均可解决。
