在开始部署之前，请确保拥有以下三个必要项：

  • ✅ 一个 GitHub 账号（已包含你的项目仓库 baoge456/wenzhangshengchengqi）

🔗 导入 GitHub 仓库

登录 vercel.com 后，在 Dashboard 点击 Add New → Project。

  1. 在 “Import Git Repository” 列表中找到 baoge456/wenzhangshengchengqi。
  2. 若仓库很多，可直接搜索关键词 wenzhangshengchengqi。
  3. 点击 Import — Vercel 会自动识别为 Next.js 项目。
✅ 框架预设: Next.js
✅ 构建命令: npm run build
✅ 输出目录: .next

根目录及其他配置保持默认即可，无需额外修改。

3

🔐 配置环境变量 (最重要!)

注意：Vercel 不会读取仓库中的 .env 文件，也绝不会在服务器上生成 .env。密钥通过加密方式注入到 process.env。

  • 在 Import 完成后的配置页面，找到 Environment Variables 区域 → 点击 Add Variable。
  • Name 输入: GEMINI_API_KEY
  • Value 输入: 你的真实 Gemini API Key
  • Environment 选项：勾选 Production、Preview、Development (三个环境都勾选，保证本地预览和生产一致)。
  • ⚡ 务必点击🔒图标标记为 "Secret"，这样密钥会被安全加密存储，永远不会泄露。
⚠️ 常见误区：
• 即便本地有 .env 文件，Vercel 也不会自动读取。
• 如果部署后文章生成失败，优先检查此处变量是否添加、值是否有效、是否触发了新的部署。

⚙️ 部署 & 自动化流水线

点击 Deploy 按钮，Vercel 将自动执行构建并通过 CDN 发布。通常 1~2 分钟就能完成。

部署成功后，您会看到类似以下的域名：https://wenzhangshengchengqi.vercel.app 。同时，Vercel 会为每个 commit 生成唯一的预览链接。

🔁 自动部署特性：
今后当你执行 git push origin main 时，Vercel 会自动重新部署并更新线上版本，无需任何手动操作。
5

🧹 根治 .env 隐患 & 重新部署技巧

如果你发现 GitHub 仓库中曾经不小心提交过 .env 文件，请立即执行以下命令清理并使其不再被跟踪：

git rm --cached .env
echo ".env" >> .gitignore
git add .gitignore
git commit -m "移除 .env 并更新忽略规则"
git push origin main

完成之后，Vercel 的环境变量仍然保留，但需要手动触发一次重新部署（让新的构建感知到环境变量变更）。

如何手动重新部署：

  • 前往 Vercel 项目 → Deployments 选项卡 → 点击最新部署右侧的「...」→ Redeploy with existing Settings。
  • 或者进入项目 Settings → Environment Variables 确认变量存在后，点击顶部 “Redeploy” 按钮。
  • 如果依旧失败，可以尝试 Clear Build Cache (Settings → General → Build Cache)。
❗ 删除仓库中的 .env 并不会导致 Vercel 环境变量丢失，但需要重新部署来使构建系统读取最新的环境变量注入。只要后台密钥存在，重新部署即可恢复。
6

🔒 将仓库设为私有 (不影响 Vercel)

担心代码公开？可以随时将 GitHub 仓库改为 私有 (Private)。已授权的 Vercel 仍然拥有部署权限，部署的服务不会中断。

  1. 进入 GitHub 仓库 → Settings → Danger Zone。
  2. 点击 Change visibility → Make private。
  3. 确认仓库名称后立即生效。
✅ 个人账号下的私有仓库，Vercel Hobby 套餐完全支持。组织私有仓库则需升级 Pro 计划。你的账号 baoge456 为个人账号，可放心设为私有。
