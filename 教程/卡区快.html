🧰 Pi Node 排障急救手册 testnet2 · 历史档案修复 · 卡顿自救

✅ 覆盖「测试网暂停出块」「状态文件卡死」「网络分区/节点孤立」「频繁重启」等真实场景。
所有命令均在 Windows PowerShell 中执行。

🔍 第一反应 · 黄金诊断

30秒找出病因

⭐ 方法一：进入容器查看（最可靠，推荐）

docker exec -it testnet2 bash

进入容器后，运行：

/usr/bin/stellar-core --conf /opt/stellar/core/etc/stellar-core.cfg http-command info | grep -E "state|num|age|status|authenticated_count"

查看完成后输入 exit 退出容器。

📋 方法二：PowerShell 单行命令（不进容器）
docker exec -it testnet2 bash -c "/usr/bin/stellar-core --conf /opt/stellar/core/etc/stellar-core.cfg http-command info" | findstr "state num age status authenticated_count"
💡 结果解读宝典
• "state": "Synced!" → 完美同步 ✅
• "state": "Catching up" + 状态文件不断变化 → 正常追赶 ✅
• "state": "Connected" 持续超过5分钟 → 卡在初始化 ⚠️
• "state": "Joining SCP" → 正在加入共识，几分钟后变 Synced! ✅
• "age" 大于 1200秒 → 超过20分钟未更新区块 ⚠️
• authenticated_count 为 0 → 网络孤立/无对等节点 ❌

⚠️ 典型故障 & 定向修复

对症下药

🌐 Pi Testnet 暂停出块 概率较高

特征： 节点显示 Synced! 但 age 超过 1 小时，Latest block 长时间不变，对等节点正常（≥5）。

本质： 测试网官方共识停顿，非节点故障。

✅ 解决方案： 无需操作，等待官方恢复。每日用诊断命令观察 age 即可。

⛔ 状态文件卡住 概率中等

特征： state: Catching up 但状态文件名一直不变，age 持续增长（>30分钟无推进）。

根源： 不支持断点续传 + 网络波动导致任务僵死。

🔧 快速恢复（按顺序）

  • ① 重启 stellar-core
  • ② 清理临时下载文件
  • ③ 完整重启容器

🔌 网络分区 / 孤立 概率较低

特征： authenticated_count : 0，节点无法同步。

原因： 防火墙/端口限制、DNS问题、ISP阻断。

🛠️ 修复手段： 检查路由器端口映射 (31400-31403)，重启路由器+电脑，重启 stellar-core。

🧩 黄金法则： 无论哪种故障，优先执行「重启 stellar-core」，70% 的卡死问题可以瞬间解决。

⚡ 万能修复工具箱

一键复制 · 立即执行
🔄 重启核心服务 (最常用)
docker exec -it testnet2 supervisorctl restart stellar-core
🧹 清理临时下载 + 重启 (卡状态文件时必用)
docker exec -it testnet2 bash -c "supervisorctl stop stellar-core; rm -rf /opt/stellar/core/buckets/tmp/*; supervisorctl start stellar-core"
♻️ 完全重启容器 (网络彻底重置)
docker restart testnet2
🔗 检查对等节点数量
docker exec -it testnet2 bash -c "/usr/bin/stellar-core --conf /opt/stellar/core/etc/stellar-core.cfg http-command info" | findstr "authenticated_count pending_count"

📜 根本性修复：历史档案 URL 证书错误

一次配置 · 永久生效
🚀 一键替换错误域名 (解决SSL/下载卡死根源)
docker exec -it testnet2 bash -c "sed -i 's/history.temp.testnet2.minepi.com/history.testnet2.minepi.com/g' /opt/stellar/core/etc/stellar-core.cfg && supervisorctl restart stellar-core"
🧠 为什么这很重要？ Pi Node 默认可能指向临时历史归档 temp.testnet2，其 HTTPS 证书已失效，导致状态文件下载永久卡住。
替换为正式域名 history.testnet2.minepi.com 后，90% 的同步卡死问题都会彻底消失。

📉 频繁崩溃/自动重启 诊断

stuck in crash loop
👀 查看最近重启记录
docker exec -it testnet2 tail -40 /var/log/supervisor/supervisord.log | findstr "exited spawned FATAL"
🩺 检查容器资源
docker stats testnet2 --no-stream

🧭 完整排障决策树

3 步定位问题
🚦 步骤1： 运行「黄金诊断」（推荐进入容器方式）→ 查看 state / age / 状态文件。
🔍 步骤2： 根据症状选择场景：
  ➜ age > 1800秒 + state: Synced! → 测试网暂停，等待恢复。
  ➜ state: Catching up + 状态文件不变 → 下载卡死 → 清理临时文件+重启。
  ➜ state: Connected 超过5分钟 → 卡在初始化 → 重启 stellar-core。
  ➜ authenticated_count = 0 → 网络分区 → 重启路由器+电脑。
⚙️ 步骤3： 以上无效，执行「历史档案 URL 修复」。
🏁 终极恢复 (顽固卡顿)
docker exec -it testnet2 bash -c "sed -i 's/history.temp.testnet2.minepi.com/history.testnet2.minepi.com/g' /opt/stellar/core/etc/stellar-core.cfg && supervisorctl stop all && rm -rf /opt/stellar/core/buckets/tmp/* && supervisorctl start all"
📌 经验备忘录： 网络故障后最容易出现「状态文件卡死」+「age 飙升」。
⚡ 最快恢复命令：docker exec -it testnet2 supervisorctl restart stellar-core
