🔧 Pi Node 急救站 certificate error · 历史档案修复

✅ 检测到 history.temp.testnet2.minepi.com HTTPS 证书失效 → 导致状态文件卡死、Local block number 停滞。
🚀 一键替换为正式档案源 history.testnet2.minepi.com，瞬间恢复同步能力。

⚡ 极速一键修复 (推荐)

Windows PowerShell | WSL 通用
📋 复制整段命令 → 在 PowerShell 中粘贴回车
docker exec -it testnet2 bash -c "sed -i 's/history.temp.testnet2.minepi.com/history.testnet2.minepi.com/g' /opt/stellar/core/etc/stellar-core.cfg && supervisorctl restart stellar-core && sleep 3 && /usr/bin/stellar-core --conf /opt/stellar/core/etc/stellar-core.cfg http-command info | grep -E 'state|ledger.num|status'"
🔍 这条命令做了什么？
• 自动修正 stellar-core 配置中的历史档案URL
• 重启核心服务 stellar-core
• 立即输出修复后的节点状态（state / ledger.num / status）
✅ 执行后若看到 "state" : "Catching up" 或 "Connected" + 正在下载状态文件，即表示修复成功！

🛠️ 手动修复 & 常见交换文件错误解决

容器内操作
  • 1. 进入容器环境
    docker exec -it testnet2 bash
  • 2. 若遇到 ".swp 交换文件警告" (E325)
    先删除残留交换文件：rm -f /opt/stellar/core/etc/.stellar-core.cfg.swp
  • 3. 手动替换错误域名
    sed -i 's/history.temp.testnet2.minepi.com/history.testnet2.minepi.com/g' /opt/stellar/core/etc/stellar-core.cfg
  • 4. 重启 stellar-core 服务
    supervisorctl restart stellar-core
  • 5. 验证修复效果
    /usr/bin/stellar-core --conf /opt/stellar/core/etc/stellar-core.cfg http-command info | grep -E "state|ledger.num|status"
    • 💡 如果容器内没有 sed 命令，请先执行 apt-get update && apt-get install -y sed 再继续。

    📡 同步状态监控工具箱

    实时诊断 | 日志跟踪
    🔎 快速查看同步进度 (状态/区块/详情)
    docker exec -it testnet2 bash -c "/usr/bin/stellar-core --conf /opt/stellar/core/etc/stellar-core.cfg http-command info | grep -E 'state|ledger.num|status|peers.authenticated_count'"
    ⏱️ 每20秒自动刷新同步状态 (Windows + WSL)
    watch -n 20 'docker exec -it testnet2 bash -c "/usr/bin/stellar-core --conf /opt/stellar/core/etc/stellar-core.cfg http-command info | grep -E \"state|ledger.num|status\""'
    📟 跟踪容器实时输出 (验证下载状态文件)
    docker logs -f testnet2 --tail 50
    ✅ 验证历史档案URL是否已替换成功
    docker exec testnet2 grep "history.*minepi" /opt/stellar/core/etc/stellar-core.cfg
    🧠 解读指南 — 修复成功后：
    • "state": "Catching up" + 显示 Downloading state file → 正常追赶。
    • ledger.num 初期保持在 8856191 不动，但状态文件名逐渐变化 (例如 89e6 → 89e7) 说明下载正常。
    • 最终 ledger.num 会瞬间跳跃至 900万以上，表示快照应用成功。
    • 若状态一直卡 Connected 且无下载动作，请再次检查配置是否含有 temp.testnet2。

    🔍 深度诊断 & 服务自愈

    高级维护
    ⚙️ 查看所有容器服务状态 (postgresql/stellar-core/horizon)
    docker exec testnet2 supervisorctl status
    🔄 单独重启 stellar-core (配置生效)
    docker exec testnet2 supervisorctl restart stellar-core
    🗑️ 清除失效swap文件 (解决vi编辑报错)
    docker exec testnet2 rm -f /opt/stellar/core/etc/.stellar-core.cfg.swp
    📊 容器资源使用监控 (CPU/内存)
    docker stats testnet2 --no-stream
    🚦 故障排查指引
    - 如果一键修复后仍长时间 Local block number 不变且无 Downloading state file，请手动执行 docker logs --tail 100 testnet2 观察有无 SSL/TLS 错误。
    - 若提示 sed: command not found，请进入容器运行 apt update && apt install -y sed 后再修复。
    - 所有命令均在 Windows PowerShell / 命令提示符 中运行，需要提前安装 Docker Desktop 并启用 WSL2。
    🎯 修复完成的标志： 在 Pi Node 界面或者上述状态命令中看到 "Catching up to ledger XXXXX: Downloading state file history/00/89/…"
    并且状态文件名称逐步推进，Local block number 最终从 8856191 跃升至 9,0xx,xxx，证明节点已彻底恢复并同步中。

    💡 提示：修改配置后第一次重启同步可能需要 10~30 分钟才显示下载进度，请保持容器运行，避免频繁重启。
