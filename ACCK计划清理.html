ACCK 计划清理 v1.0

Docker 容器日志 + apt 缓存 + journal 定期清理方案

✅ 适用于 Debian / Ubuntu 🐳 依赖 Docker ⏱ 每周一凌晨 3:00
1

创建清理脚本

在 /root/clean_system.sh 写入以下内容。脚本会依次清空容器日志、清理 apt 缓存、精简 journal（保留 50M），不会删除 certbot 镜像，也不会执行 apt autoremove。

bash 
cat > /root/clean_system.sh <<'EOF'
#!/bin/bash
# 系统定期清理脚本
# 功能：清空 Docker 容器日志、清理 apt 缓存、精简 journal
# 注意：不删除 certbot 镜像（证书续期依赖），不执行 apt autoremove（避免误删）

echo "=========================================="
echo "清理开始: $(date '+%Y-%m-%d %H:%M:%S')"
echo "=========================================="

echo "=== 清理前 ==="
df -h /

echo ""
echo "=== 清空容器日志 ==="
truncate -s 0 /var/lib/docker/containers/*/*-json.log
echo "已清空所有容器 json.log"

echo ""
echo "=== 清理 apt 缓存 ==="
apt-get clean
echo "apt 缓存已清理"

echo ""
echo "=== 清理 journal（保留 50M）==="
journalctl --vacuum-size=50M

echo ""
echo "=== 清理后 ==="
df -h /

echo ""
echo "清理完成: $(date '+%Y-%m-%d %H:%M:%S')"
echo "=========================================="
EOF
💡 说明： certbot 镜像保留是因为续期脚本 auto_cert_renewal.sh 依赖它；不执行 autoremove 是为了避免误删系统依赖。
2

赋予执行权限

让脚本可执行。

bash 
chmod +x /root/clean_system.sh
3

手动执行验证

先手动跑一次，确认输出正常、无报错。

bash 
/root/clean_system.sh
📌 预期输出： 清理前后会各打印一次 df -h /，中间显示各步骤执行情况。journal 显示 freed 0B 是正常的（未达到 50M 阈值）。
4

添加定时任务

备份当前 crontab，然后追加每周一凌晨 3:00 执行的任务（自动去重）。

bash 
# 备份当前 crontab
crontab -l > /root/crontab_backup_$(date +%Y%m%d).txt

# 追加新任务（自动去重）
( crontab -l 2>/dev/null | grep -v "clean_system.sh" ; echo "0 3 * * 1 /root/clean_system.sh >> /var/log/clean_system.log 2>&1" ) | crontab -

定时规则解读： 0 3 * * 1 表示每周一 03:00 执行，输出追加到 /var/log/clean_system.log。

5

确认定时任务已生效

查看当前 crontab 列表，确认新增行已存在。

bash 
crontab -l

应能看到类似以下内容（最后一行是新增的）：

output 
*/30 * * * * /usr/freemem.sh >> /tmp/tmp.txt
0 0 * * * ~/auto_cert_renewal.sh
0 2 * * * docker exec nginx apk add logrotate && docker exec nginx logrotate -f /etc/logrotate.conf
@reboot sleep 30 && pgrep -f 'cf-vps-monitor|vps-monitor-service' >/dev/null || /root/.cf-vps-monitor/bin/vps-monitor-service.sh
@reboot iptables-restore < /etc/iptables/rules.v4
0 3 * * 1 /root/clean_system.sh >> /var/log/clean_system.log 2>&1
📋

后续维护与排查

操作 命令
查看最近清理日志 tail -50 /var/log/clean_system.log
手动应急清理 /root/clean_system.sh
恢复 crontab 备份 crontab /root/crontab_backup_YYYYMMDD.txt
查看磁盘使用 df -h /
⚠️ 注意： 该脚本针对 Debian/Ubuntu + systemd + Docker 环境。若迁移到 CentOS/RHEL，请将 apt-get clean 替换为 yum clean all。非 Docker 环境可移除日志清理部分。
🔍

适用性速查

环境 是否适用 调整建议
Debian / Ubuntu + Docker ✅ 直接使用 无需修改
CentOS / RHEL ⚠️ 需修改 apt → yum
非 systemd 系统 ⚠️ 需修改 移除 journalctl 行
无 Docker 环境 ⚠️ 需修改 移除 truncate 行
磁盘充裕（<70%） 💤 不必要 可加阈值判断或跳过
💡 通用化建议： 在脚本开头加入磁盘使用率阈值判断，例如 usage=$(df / | awk 'NR==2 {gsub("%",""); print $5}')，超过 85% 才执行清理。长期方案建议配置 Docker 日志轮转（max-size=10m，max-file=3）。
